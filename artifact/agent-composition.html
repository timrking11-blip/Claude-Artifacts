Account Research Composition

Three agents in a chain, one shared session state, and six tools that only research_agent may call. The user supplies a company; the chain ends in a five-section account brief drawn from the CRM master ledger, the company's website, and — when enabled — Google Cloud's BigQuery and Agent Registry MCP servers.

The run, turn by turn

This is a real sequence: research_agent's prompt orders its steps, and each one depends on the last.

  1. root_agent asks for the account if you haven't named one, then calls find_account. OK stores account and transfers. AMBIGUOUS shows the candidates and asks. NOT_FOUND says the ledger has no contacts there and asks for another — it never invents.
  2. research_agent calls list_account_contacts — every ledger contact at the account, ordered by seniority, with which channels we hold (email / phone / LinkedIn).
  3. …then assess_ledger_quality — missing email, phone or title; single-source records; anything not updated in 90 days; manual edits; contacts Explorium hasn't enriched yet.
  4. …then, if the account has a domain, fetch_page on its website (HTML stripped to text, capped at 20k characters) and summarize_page_agent to reduce it to what the company does, who it serves, and any news. A fetch error is stored as the summary, not swallowed.
  5. …then, if a BigQuery tool is attached, a look for the account in the warehouse; otherwise warehouse_findings is stored as "Not available in this session".
  6. analysis_agent receives the state and writes the brief: at a glance · who we know · coverage gaps · data-quality actions · suggested next step. Specific names, titles and counts; unknowns stated as unknown.

Guardrails and where it runs

Rate limit

rate_limit_callback on every agent: 1000 model calls per 60 s, then sleep. Unchanged from the template.

Degrades, doesn't crash

MCP tools attach only with ACCOUNT_RESEARCH_ENABLE_MCP=1 and Application Default Credentials; otherwise the agent runs without them. Optional prompt keys render empty rather than raising.

Model

Claude on Vertex AI by default — claude-fable-5-1 through ADK's Claude wrapper (AnthropicVertex, ADC auth, region global); ACCOUNT_RESEARCH_MODEL_PROVIDER=gemini switches to Gemini.

Three ways to run

adk web . for development · python main.py as a FastAPI service on $PORT for Cloud Run · deployment/deploy.py to Agent Runtime.

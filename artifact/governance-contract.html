Governance Contract C1–C8

One rulebook for every write in the stack. The Engagement Operating System states the invariants; each clause below restates one of them as a rule a routine, a page or a script applies at the moment it writes.

v1.0 · 25 September 2026 · Owner: Timothy King · Source: Unified Architecture Blueprint, 24 Sep 2026

Today the same eight rules are written four times: EOS G1–G6, the SWAT cockpit's AI spec, the P3 and P4 specs, and the atlas guardrails. From here on they are written once, on this page, and everything else cites the clause.

The eight clauses

Each clause, its EOS invariant, and where it already applies

"Where it applies today" lists the places that already state the rule in their own words. "In code" names what the repository enforces now; the rest is enforced by the routine prompts and the pages until the governance library ships in Phase 4.

  1. C1

    Generated records start as draft; state changes only by a recorded acceptance.

    EOS invariant
    G1 Draft, not final and Stage 5, "no acceptance, no advance"
    Applies today
    • SWAT: nothing silently finalizes
    • P4 writes authorship='ai', status='raw'
    • Composition review: HOLD lines, needs_founder; agents never write stage
    In code
    crm/runlog.py holds any run that would create more than 5 records until the owner confirms that exact count
  2. C2

    A run reads only the scope it was given, recorded in its manifest.

    EOS invariant
    G2 Input-bounded
    Applies today
    • P4: the bundle holds only listed assertions; the "no invention" trigger
    • The intake-domain guardrail on composition runs
    In code
    crm/guardrails.py domain lock and credit-spend check, applied at scripts/compose_account.py finalize
  3. C3

    No claim without a source row or an evidence tag.

    EOS invariant
    G4 Traceable with the tags S supported, U unsupported, N needs stipulation
    Applies today
    • SWAT: a source pointer, or the claim is auto-flagged
    • P4: v_ungrounded_swot fails the build
    • Composition runs: data/runs sources and coverage files
  4. C4

    One call site per provider.

    EOS invariant
    G3 Model-agnostic
    Applies today
    • ADK provider switch: anthropic · claude on Vertex · gemini
  5. C5

    Criteria are signed off before collection and never enter a synthesis bundle.

    EOS invariant
    G6 Kill/pivot pre-agreed
    Applies today
    • P3: decide the DC1 threshold before ST7 runs; thresholds stay hidden from the model
    • GTM Control: kill thresholds are "not renegotiable after"
  6. C6

    Missing data is a sentinel value, never a blank or a default.

    EOS invariant
    N Needs stipulation (evidence classification)
    Applies today
    • P3: absent from a website is unknown, never false
    • Atlas: sentinel vs unset; write "not available"
    In code
    crm/guardrails.py "empty means empty": nothing on the intake domain makes the proposal a not-found note
  7. C7

    Empty never overwrites; every write is version-pinned; owners are fixed per field.

    EOS invariant
    S5 Human edits recorded (Stage 5, Refresh & Human Governance)
    Applies today
    • SWAT P6 gate: refresh "without wiping accepted human edits"
    • P4: the hash check refuses a stale bundle
    • Atlas: the empty-value rule, pinned writes (if_version), field ownership (the Apollo sync never writes CRM-owned fields)
  8. C8

    Nothing is deleted; every state change is logged with who and when.

    EOS invariant
    G5 Auditable and the decision log
    Applies today
    • P4: bundle manifest and sha256
    • CHANGELOG, the meta/sync changelog, void proposals kept
    In code
    crm/runlog.py writes one line per run to the CRM's runlog, which the CRM page and the morning brief show
Using the contract

How the rest of the stack refers to it

Cite the clause

A routine prompt, page or script that writes records names the clauses it applies, for example "RULES: contract C1–C8". The scheduled blueprint routines already do.

Change it here only

A clause changes by a new version of this page, recorded in the CRM Systems Atlas registry changelog. The pages that cite it link here instead of restating it.

Into code in Phase 4

The governance library (T5, crm/governance.py) implements C1–C8 with tests and is called by the composition run's finalize step and the P3/P4 collectors.

Linked from the Engagement Operating System, the P4 Contextualization Spec and the contingencies on the Account Composition Intake.

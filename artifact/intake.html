Account Composition Intake

Paste the LinkedIn request, name the account, press Run composition. The research agents read the ledger, crawl the company's site and the open web, draft the SMI prequalification proposal and file it into the CRM (the contact's notes, or the account's for a new prospect); the review, the note to the founder and the proposal show up below, with a PDF to download. This is the only way proposals are made. Nothing to copy into a terminal.

01

Precondition

Resolved by find_account against the enriched data layer. An account that is not there still runs (the review says so), but nothing runs without a name or domain. The domain is the specification: the run researches the company at this domain only; a similarly named company at another domain is never used, and when nothing is found here the proposal is a not-found note.

03

CRM disposition

Composed accounts have to land somewhere. Choose before running, because the two paths mint different record ids.

Check before choosing Apollo. Account ingest reads the lists in meta/config.account_lists. The Strategic Market Insights list was re-added on 24 Sep 2026. The run reads that setting first; if it is ever empty again the review HOLDs until the list id is back or you switch to manual.
04

Run

One press writes the run record and wakes the session that owns the repo. In order: re-gate the manifest → ledger tools → the company's site → Apollo and Vibe Prospecting → open-web research (company, market, competitors, adjacent, macroeconomics) → the SMI proposal with a ValueFirst "why now" → the review and the note to the founder → one merged note into the CRM record's pre-qual phase, with the Apollo and CRM sync schedule that follows. Each step reports back here as it returns.
